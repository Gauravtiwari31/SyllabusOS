# Android app (APK) for SyllabusOS

The app is a **Trusted Web Activity (TWA)**: a real Android app that opens your deployed site full screen in Chrome's engine. Everything is free. Google sign-in keeps working (Google blocks sign-in inside plain WebView wrappers, but a TWA runs in Chrome), and every website deploy updates the app instantly without a new APK.

Already prepared in the code:

| What | Where |
|---|---|
| Web app manifest (name, colours, start page, shortcuts) | `app/manifest.ts` → `/manifest.webmanifest` |
| Icons (192/512, maskable 192/512) and favicon | `public/icons/`, `app/icon.svg`, `app/apple-icon.png` |
| Offline screen and service worker | `public/offline.html`, `public/sw.js` |
| Digital Asset Links: the app's package and signing keys are built in, env vars can add more | `/.well-known/assetlinks.json` → `app/api/android/assetlinks/route.ts`, `lib/android/assetlinks.ts` |
| Android project (TWA, generated by Bubblewrap), portrait and landscape | `android/` |
| Keystores, signing passwords and build output ignored by git | `.gitignore` (`android/*.keystore`, `*.jks`, `keystore.properties`, `*.apk`, `*.aab`) |

## Before you start

- The site is deployed on Vercel over HTTPS (see [DEPLOY_VERCEL.md](DEPLOY_VERCEL.md)).
- JDK 17 and the Android SDK (platform 36, build-tools 35+) are installed, e.g. through Android Studio.
- Gradle finds the SDK through `ANDROID_HOME` or `android/local.properties` (`sdk.dir=C:/Users/<you>/AppData/Local/Android/Sdk`).

## 1. The Android project

`android/` was generated with Bubblewrap from `https://<your-domain>/manifest.webmanifest`. The settings that matter:

| Setting | Value |
|---|---|
| Application ID | `com.syllabusos.app` (**can never change after you publish**) |
| Start page | `/dashboard` |
| Display / orientation | `standalone` / `any` (follows the device and its rotation lock) |
| Status bar / navigation / splash colours | `#000000` |
| Version | `versionCode` / `versionName` in `android/app/build.gradle` (mirrored in `twa-manifest.json`) |

To regenerate it from scratch, run `npx @bubblewrap/cli init --manifest https://<your-domain>/manifest.webmanifest` in an empty `android/` folder and give the answers above.

## 2. Signing key

Release builds are signed with the key described in `android/keystore.properties` (never committed):

```properties
storeFile=release.jks
storePassword=<password>
keyAlias=syllabusos
keyPassword=<password>
```

Create a key once (PKCS12 keystores use one password for the store and the key):

```bash
keytool -genkeypair -keystore android/release.jks -storetype PKCS12 -alias syllabusos -keyalg RSA -keysize 2048 -validity 10000
```

**Back up `release.jks` and `keystore.properties`** somewhere safe (not in git). If you lose them you can never publish an update to the installed app.

## 3. Build

```bash
cd android
```

```bash
./gradlew assembleRelease bundleRelease
```

On Windows use `gradlew.bat`. You get:

- `android/app/build/outputs/apk/release/app-release.apk` (install and share)
- `android/app/build/outputs/bundle/release/app-release.aab` (Play Store)

## 4. Link the app to the website (removes the URL bar)

Android opens the app full screen only when `https://<your-domain>/.well-known/assetlinks.json` lists the APK's package name and signing-key fingerprint. Otherwise it falls back to a Chrome tab with an address bar.

The package and the fingerprints of the project's keys are built into `lib/android/assetlinks.ts`, so every deployment already serves them. If you sign with a different key (or Google Play re-signs the app, step 8), print its fingerprint:

```bash
keytool -list -v -keystore android/release.jks -alias syllabusos
```

Then either add it to `ANDROID_APP.fingerprints` in `lib/android/assetlinks.ts`, or set these in Vercel → Settings → Environment Variables (Production) and redeploy:

| Name | Value |
|---|---|
| `ANDROID_PACKAGE_NAME` | `com.syllabusos.app` |
| `ANDROID_SHA256_CERT_FINGERPRINTS` | the SHA256 value (more than one? separate with commas) |

Check that `https://<your-domain>/.well-known/assetlinks.json` shows the package and fingerprint, or ask Google's checker:
`https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://<your-domain>&relation=delegate_permission/common.handle_all_urls`

## 5. Install on your phone

Copy the APK to the phone and open it (allow **Install unknown apps** for your file manager when asked), or with the phone connected over USB with USB debugging on:

```bash
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

The app should open full screen with no address bar. If a URL bar shows, `assetlinks.json` doesn't match the APK (step 4): fix it, redeploy, then clear Chrome's storage for your domain (or reinstall the app).

## 6. Share with testers: Firebase App Distribution (free, Spark plan)

1. [Firebase console](https://console.firebase.google.com) → **Add project** (Analytics optional).
2. **Add app → Android** → package name `com.syllabusos.app` → register. Skip the SDK and `google-services.json` steps; the app doesn't need them.
3. **Release & Monitor → App Distribution → Get started**.
4. Drag in `app-release.apk`, add testers' emails (or a tester group), add release notes, **Distribute**.

Testers get an email, install the Firebase App Tester app once, and install SyllabusOS from there. Each new APK you upload notifies them.

## 7. Updating the app

- **Website changes** (features, fixes, design): just deploy to Vercel. The app shows them immediately.
- **App changes** (name, icon, colours, start page): edit `android/app/build.gradle` (and `twa-manifest.json` to keep Bubblewrap in sync), increase `versionCode` and `versionName`, rebuild (step 3) and upload the new APK to App Distribution.

## 8. Google Play (optional, one-time $25 developer fee)

1. Play Console → create the app → upload `app-release-bundle.aab` to an internal testing track first.
2. Play re-signs the app. Copy the **App signing key certificate SHA-256** from Play Console → Test and release → Setup → **App signing**.
3. Add it to `ANDROID_SHA256_CERT_FINGERPRINTS` (or `lib/android/assetlinks.ts`) and redeploy. Without it, the Play Store version shows a URL bar.

## Troubleshooting

| Symptom | Fix |
|---|---|
| URL bar at the top | `assetlinks.json` doesn't match: check package name and fingerprint (step 4), redeploy, reinstall. |
| `assetlinks.json` shows the 404 page | The route was left out of the deployment. `.vercelignore` must say `/android/` (anchored): a bare `android/` also drops `app/api/android/`. |
| Gradle: "Unable to establish loopback connection" | Something (a sandbox, VPN or firewall) blocks local sockets for Java. Run the build from a normal terminal. |
| "App not installed" | An older build signed with a different key is installed. Uninstall it first. Builds before 1.1.0 used the package `com.crazycoders.syllabusos`; they install side by side and can be removed. |
| Blank or "You're offline" screen | No connection; the app needs the internet for the tutor and plan. |
| Google sign-in fails | Add the production origin and redirect URI in Google Cloud and set the consent screen to "In production" ([DEPLOY_VERCEL.md](DEPLOY_VERCEL.md), step 7). |
